# Protocolo CLARO para la comunicación de equipos virtuales

## Descripción

El **Protocolo CLARO** es una estrategia para organizar la comunicación de un equipo de desarrollo de software que trabaja de forma virtual.

La propuesta integra prácticas de comunicación asertiva, netiqueta, uso adecuado de hilos y prioridades, herramientas colaborativas, ownership de documentos, organización de reuniones remotas y un plan de fallback ante posibles fallos técnicos.

Su objetivo es mantener una comunicación clara, respetuosa y organizada, evitar la pérdida de información y definir responsabilidades dentro del equipo.

## C - Comunicación asertiva

Los integrantes deberán expresar sus ideas de forma clara y respetuosa, evitar mensajes ambiguos o incompletos, validar la información recibida y utilizar el canal adecuado según el tipo de mensaje.

También se aplicará responsabilidad digital mediante el respeto a los tiempos de respuesta, el uso adecuado de los canales y el cumplimiento de los acuerdos establecidos.

## L - Líneas de conversación y prioridades

Cada tema deberá mantenerse dentro de su hilo correspondiente para evitar mezclar conversaciones y perder información.

## A - Asignación y ownership

Se utilizarán **GitHub Issues** para registrar tareas, errores y mejoras, así como para dar seguimiento al progreso del trabajo.

Cada Issue deberá incluir:

- Título claro.
- Descripción.
- Prioridad.
- Responsable.
- Estado.
- Criterio de finalización.

Además, los documentos importantes tendrán un **owner**, es decir, una persona responsable de mantener actualizada y organizada la versión oficial, controlar cambios relevantes y evitar duplicidad de información.

## R - Reuniones remotas

Cada reunión contará con dos roles:

- **Moderador:** guía la reunión, facilita la participación y mantiene el enfoque en los objetivos.
- **Timekeeper:** controla el tiempo asignado, evita desviaciones innecesarias y asegura el cumplimiento de la agenda.

Al finalizar cada reunión se registrarán las decisiones tomadas, tareas pendientes, responsables y fechas correspondientes.

## O - Operación ante fallos

El equipo contará con un plan de fallback para mantener la continuidad del trabajo ante problemas técnicos.

- Si falla el audio, se continuará mediante chat.
- Si falla la videollamada, se utilizará un canal alternativo.
- Si un integrante pierde la conexión, se le compartirá posteriormente un resumen de los acuerdos.
- Si ocurre una falla general del servicio, la reunión se reprogramará de forma organizada.
- Cuando sea posible, GitHub Issues permitirá continuar el trabajo de forma asíncrona.

## Resultado esperado

La aplicación del Protocolo CLARO busca mejorar la comunicación, coordinación y organización del equipo virtual, reduciendo malentendidos y asegurando que las tareas, decisiones y responsabilidades queden claramente establecidas.
